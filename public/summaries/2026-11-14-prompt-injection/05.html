就算注入成功，
也换不来效果
前两层都在跟模型的判断较劲；这一层不跟模型讲道理，只管宿主机的真实效果。
read-only workspace-write danger-full-access
模式只管文件效果；网络和进程可见性不在其中——文档写得很直白，不装作全覆盖。
[sandbox: file access denied under <mode> mode]
拒绝是这条固定文本。bash 工具的描述里还写死了后半句：
a blocked file operation is reported as `[sandbox: file access denied under <mode> mode]`, a policy denial: do not retry another way.
packages/shell/tool-bash/src/index.ts:98
因为模型最常见的绕过不是提权，而是换一条路径再试一次。
唯一出口
同一轮次里，模型可以带最窄的更宽模式加一句 justification，把同一条命令重试一次。这次重试触发审批，被拒绝就是这条命令的终局。
升权不是模型的能力，是用户的决定。
审批 fail-closed · 只有四种结果
allowed-once rejected cancelled unavailable
没应答者、应答者抛异常、返回值不在词表——一律归一成 unavailable，按拒绝处理；never 策略下每次询问直接 rejected，连分发都不做。
审批请求不复制一份工具参数，界面把提示挂在已经流式展示的那次调用上——避免两份参数各自漂移，人看到的就是要执行的那条。
