点「选择目录」后发生什么？

桌面能力经 preload 注入全局对象，客户端用存在性探测（optional chaining）消费：
dshDesktop
原生保存 · 原生拖放 · 更新频道 · 凭据引导 · transcript 视图
dshOnboarding
onboarding 凭据与 Desktop 入口（ui-settings-account）
dshDesktopBoot
桌面 vs 浏览器 boot 的唯一分岔
__DSH_DIRECTORY_PICKER__
原生目录选择
__DSH_HOST_PATHS__
会话输入框的 @path 文件引用（ui-conversation）
__DSH_LOCALE__
语言引导与变更通知
dshPlatform
Usage / Top-up 嵌入视图
欢迎窗口另用 dshWelcome，属于壳自己的一套全局，不在 dshDesktop 体系内。
const pick = desktop === undefined
  ? () => ctx.uiWorkspace.pickDirectory()  // Web
  : () => desktop.pick()                    // Electron
同一个功能，按端选通道；Host 侧自动选择还会因缺图形工具（zenity / kdialog）、远程会话、无图形显示等条件降级为 browse 列表。
空壳兜底：完整 dshDesktop API 只在 dsh-app://app 主 frame 暴露，其余文档只拿到 protocolVersion: 1 空壳（其余桥只按 protocol + hostname 暴露）；主进程 assertProductSender 逐次校验，boot 类 handler 另用 assertDesktopSender。
依赖图纪律：全部桥由 preload 定义，client 包不 import electron、不按载体做条件编译；但仍有本地 ./electron/* 模块与 dsh-app: 协议白名单，不是「零平台知识」。
