REFUSAL · 0.2.2-RC.4 此前的问题

拒答，曾被当成
「响应格式错误」

DeepSeek 官方 API 在内容安全审查不通过时，会以 stop_reason: "refusal" 结束流——官方文档要求调用方处理这个终止原因。rc.3 的适配器没认，直接当成格式损坏。

// rc.3 的 stopReason()：四种停止原因之外一律兜底
case 'end_turn': case 'tool_use': …
default: malformed(`unsupported stop reason ${raw}`)
// DeepSeek 以 refusal 结束流时 ↓
→ MALFORMED_RESPONSE // "unsupported stop reason refusal"
01
语义错位
提供方拒绝回答，用户看到的却是「格式错误」，
排查方向被带偏。
02
重试错配
MALFORMED_RESPONSE 是可选重试码；
对注定再被拒的请求重试，白烧 token。

拒答是提供方的正常决定，不是格式损坏——rc.4 给它单独分类。
