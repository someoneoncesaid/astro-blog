## 三、导入机制：两遍扫描，一次一条

导入器的设计围绕一个约束：整个 zip 在内存里处理，但任何一个条目、任何一段对话都不应该能拖垮 Host。

1. 浏览器上传 `deepseek_data-*.zip`，整包先读进内存，大小受 `maxUploadBytes` 约束（默认 512 MiB）。
2. 用 fflate 异步解压，一次只展开一条目；先看条目声明的大小，超过 `maxEntryBytes`（默认 256 MiB）直接拒绝，不做无用功。
3. 第一遍扫描只记录每段对话的条目、id、标题和最后一条消息的时间；第二遍按最旧优先逐段导入，条目之间让出事件循环，每步检查取消。
4. 每段对话树线性化到最新的叶子，保留原始标题与时间；只保留最近 `maxSessions` 段，某段导入失败时用更旧的对话补足名额。
5. 写入用户在弹窗里选的 Workspace。界面按 NDJSON 流式进度显示「Importing n/K」，结束后汇总每段是导入、跳过还是失败及原因。

写入走普通持久化路径：`sessionPersistence.create` → `append` → `flush` → `close`（失败时也关闭）。header 为 `{ version: SESSION_FORMAT_VERSION, id, createdAt, cwd, isSeeded: false }`，`cwd` 是 Workspace 的规范路径。存储的事件不含 `session/end-seed`，首次打开时普通恢复路径追加该标记。导入不新增 Session 事件类型，因此导入后的会话与其他冷会话一样出现在 `session/list`，打开走普通恢复路径，也不需要持久化类型确认。

## 四、上限与安全

| 项 | 行为 |
| --- | --- |
| 单次上传 | 512 MiB（`maxUploadBytes`，整包先进内存） |
| 单条目解压 | 256 MiB（`maxEntryBytes`，先查声明大小再解压） |
| 调用者 | 仅 owner；非 owner 调用直接拒绝（含 `limits()`） |
| 并发 | 同一时刻只允许一个导入，服务持有唯一的导入槽位 |
| 取消 | 每个请求各带一个 AbortController；插件卸载时取消正在跑的导入并等待停下 |
| 调度 | 条目之间让出事件循环，大导入不阻塞 Host |

这些上限都是 Config 字段，不是硬编码：部署方可以在 cordis.yml 里改默认值。

## 五、聊天内容去了哪

**保留并转换**：reasoning、回答、web search / open 片段、导出图片，映射为现有原生事件与附件。模型看到的就是一次普通会话的内容。

**以错误收尾**：被撤回、失败、模板化的回复，对应的那一轮以错误结束，不进入模型上下文。会话记录里保留这段收尾，便于人查看，但后续请求不会把这部分当作对话历史。

四条细节规则：

- 空用户消息写为 `[empty message]`。
- 标题经 `normalizeSessionTitle`，超过 `maxTitleBytes`（默认 80）按字节截断。
- 未知状态的未完成回复用固定错误码 `DEEPSEEK_EXPORT_UNFINISHED_REPLY`。
- 被内容过滤撤回的问题，连同回复一起省略，不产生空轮。

## 七、Windows 升级目录锁修复（#8385）

安装器的「重启状态」窗口由 rundll32 启动，`CreateProcessW` 的工作目录参数传了空——进程继承安装目录。状态窗口存活期间该目录句柄被占住，升级要重命名安装目录就会被卡住。修复只有一行：显式把工作目录设为系统目录。

```cpp
// An inherited installation directory would prevent its rename while the status window is alive.
launch->directory = system;
```

完整改动见 [restart-status.h](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.3/apps/desktop/installer/restart-status.h)，含 NSI fixture 与 Windows 测试更新。Windows 自动更新用户从这版起升级不再被状态窗口锁住目录。

## 八、CI：bubblewrap 归档验证与缓存（#8383）

新增 [ci-verified-download.sh](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.3/scripts/ci-verified-download.sh) 与其 spec：下载的 bubblewrap 归档先验证再缓存，下载有上限；ci.yml 新增缓存 job，ci-master 与 e2e 工作流配套。这条只动 CI，产品代码没有变化。
