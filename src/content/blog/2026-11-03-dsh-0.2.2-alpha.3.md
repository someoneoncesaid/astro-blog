## 一、新增功能：三条主线

### 1.1 一套右键菜单，覆盖会话、工作区和侧边栏

原文：「支持统一右键与键盘菜单，覆盖会话、工作区和侧边栏，并支持开发者扩展。」

以前右键能做什么、在不同区域表现是否一致，取决于那一块界面自己实现了什么。这一版把右键和键盘菜单收成一套：会话列表、工作区、侧边栏共用同一套菜单模型，并留出扩展口给开发者往菜单里加自己的项。

- **对使用者**：同一类对象（会话、工作区）不管从哪个区域右键，菜单结构一致，不用重新找。
- **对开发者**：菜单是可扩展的，插件或自定义集成可以往里挂条目，不必另造一套浮层。
- **边界**：原文只说「覆盖」和「可扩展」，没有承诺所有内置操作都进了菜单；遇到某个操作在菜单里找不到，属于正常状态，不要当成回归。

### 1.2 文件预览有了常驻目录树和文件定位

原文：「文件预览支持常驻目录树和文件定位功能。」

这是本次最容易被低估的一条。以前预览一个文件，看完想换同级另一个文件，通常要退回资源管理或重新开一遍。现在预览区常驻一棵目录树，并且支持定位当前文件——打开某个文件时，树会自动展开到它所在的位置。

- **适合的场景**：翻一个模块的多个文件、顺着目录读一个包、连续看几个配置文件。
- **连带改动**：文本和 Markdown 预览的阅读位置现在会在刷新后保留（见 3.3），两个改动叠在一起，浏览长文件才真的连续。
- **边界**：目录树是「常驻」的，意味着它会占掉预览区的横向空间；窄屏下的表现原文没有说明，属于待验证项。

### 1.3 变更请求与工作树合成一个入口（实验性）

原文：「实验性『变更请求与工作树』统一代码审查与工作树入口，支持通过可搜索文件树和逐文件导航查看本地及 PR 差异，将选中代码和评论交给 Agent，并跟踪检查与评审状态。」

这是本次唯一称得上「新面板」的东西，也是唯一明确标了实验性的功能：

- **一个入口，两种差异**：本地改动和 PR 差异在同一个面板里看，不用在两套界面之间切换。
- **先搜索，再逐文件**：差异以文件树组织，可搜索，可按文件逐个导航，文件多了不至于滚不到底。
- **能对话**：选中的代码片段和评论可以直接交给 Agent，审查意见不用复制出去再贴进输入框。
- **能跟踪**：检查结果和评审状态在面板里可见。

配套变更：原来独立的「Git 工作树」入口已被合入这里。曾经手动启用过独立工作树插件的用户，需要自己从 profile 的 `dsh.profile.bundles` 里删掉 `@deepseek-ai/dsh-experimental-tool-worktree`，否则会留下一份不再需要、可能还和新入口打架的旧插件（见 5.3）。

实验性功能的惯例仍然适用：默认不一定开，接口和交互都可能在后续版本变动，别在关键流程上做唯一依赖。

## 二、体验优化：六处日常打磨

| # | 变化 | 实际感受 |
| --- | --- | --- |
| 2.1 | 改善手机端侧栏导航与窄屏布局，会话标题保持稳定 | 手机上不再因为标题重排而跳位 |
| 2.2 | 模型目录输入、插件发现页的操作在窄屏下完整可见 | 输入框和按钮不再被裁掉 |
| 2.3 | 菜单和浮窗优先保持在可见区域内，跟随缩放、平移、软键盘 | 浮层不再跑到屏幕外 |
| 2.4 | Trajectory 支持独立折叠子调用，保留父调用和摘要 | 长任务轨迹能按需收起来看 |
| 2.5 | 搜索或跨视图定位时可展开对应子调用 | 命中的那一层会自动展开 |
| 2.6 | 思考内容的摘要、展开正文、翻译不再显示签名前缀 | 推理内容的第一行不再是乱码串 |

补充几条原文里的细节：

- **Trajectory 折叠**不只是「能收」，而是「收起后父调用和摘要仍在」——折叠的是细节，不是上下文。定位到某个子调用时，包含它的父级也会一并展开，所以跨视图跳转不会停在空壳上。
- **思考内容的签名前缀**来自模型输出的签名字段。以前摘要、展开、翻译三处都可能把这串元数据露出来，这次统一隐藏，只处理展示层，不影响底层记录。
- **性能**一条包含两件事：减少会话状态更新时的重复发布和目录处理开销；降低长回复流式组装时的运行时成本。前者影响会话很多时的整体流畅度，后者影响长回答出来的顺滑程度。原文没有给数字，本文不补。
- **输入框稳定**指的是底部输入区的布局跳动：打字、展开菜单、统计数字刷新时高度不再反复变化。

## 三、问题修复：按「你会遇到什么」分组

原文 10 条修复，按症状重新归类，方便对号入座。

### 3.1 模型与审查链路

1. **图片超限不再一直失败**。通过 pi-ai 接入的模型，会话里的图片数量超过请求上限时，现在自动省略最早的那些图片并继续请求。以前是一路报错，整轮对话卡死。
2. **OpenCode 路由的自动审核恢复正常**。修复了自动审核在工具执行前就失败的问题，审查请求现在会带上对应会话的身份和用途。这条对开了自动审核的 OpenCode 用户是阻断级修复。

### 3.2 会话与历史

3. **空会话不再赖在列表里**。alpha.2 引入的回归：恢复后的空会话被当成「未命名」会话一直显示。修好之后，顺便恢复了按最后提示时间排序。
4. **带旧版子代理描述的历史会话能打开了**。此前这类会话打不开，还会连带把会话搜索搞挂——所以症状可能表现为「搜索没结果」，根因却在某条老会话上。
5. **压缩过的历史能继续加载**。加载更早的已压缩历史之后，聊天记录不再停止加载和更新。长会话翻历史时最容易被这条绊住。

### 3.3 文件、预览与链接

6. **Markdown 文件链接变宽容**。链接里的行号写错也能打开文件；支持行范围和「行:列」后缀；实在定位不到就打开原文件本身；以 URL 形式出现的链接仍按网页链接处理。
7. **预览记住读到哪**。文本和 Markdown 预览刷新后保留阅读位置；文件暂时变短时也保留原位置，而不是跳回第一页。
8. **历史 `run_code` 记录恢复高亮**。部分历史记录缺少 TypeScript 或 Python 语法高亮的问题修好了。

### 3.4 工具与轨迹

9. **失败工具的真实返回不再被替换**。Trajectory 的列表、详情和复制输出，都保留失败工具实际返回的文本，不再用合成的错误信息顶替；原生工具和嵌套 PTC 调用规则一致。排查失败原因时，这决定了你看到的是证据还是结论。

### 3.5 自动化任务

10. **打开已有任务，表单显示正确控件**。以前打开一个已有的定时任务，日期、时间、间隔、星期可能显示成不匹配的控件；现在直接显示对应控件，并给出字段级修正提示。只改名称或指令时，原时间规则保留；规则过于复杂或超出控件精度时，原文照旧保留，不会被表单吞掉。

## 五、升级前必看：三处默认值与一处迁移

这一节是本文的重点，也是和「更新了什么」同样重要的一半。

### 5.1 `apply_patch` 默认关闭

新增的多文件补丁工具在发布说明里明确标注为默认关闭。想用需要在工具配置里显式开启。开启后它的写盘能力比单文件编辑更强，建议配合 Review 使用，先看变更再决定是否放行。

### 5.2 「先读再改」和「外部修改防护」默认关闭

发布说明的原文是：文件修改的先读和外部修改防护默认关闭，沙箱限制和 Review 保持不变；需要原来那层防护的 profile，可以显式恢复观察策略。

这句话翻译成操作建议：

- **默认状态下**，模型改文件不再强制先读一遍，也不再因为文件被外部改过而拦下。省掉的正是「读一遍确认」的往返，代价是少了一道检查。
- **沙箱限制和 Review 没变**，所以危险操作仍然有边界，变更仍然可查。
- **如果你依赖这层防护**（比如让 Agent 在共享目录里跑），请主动把观察策略加回去，不要以为它还在默认开着。

### 5.3 工作树插件要手动清理

曾经启用过独立「Git 工作树」插件的用户，需要自己从 profile 的 `dsh.profile.bundles` 中移除 `@deepseek-ai/dsh-experimental-tool-worktree`。这一步没有自动迁移，属于必须手动确认的项。

### 5.4 其他确认项

- **Node.js**：仍是 `>= 24.9.0`，运行时版本低的话先升级。
- **预处理阶段**：这是 alpha 预发布，`apply_patch`、变更请求与工作树都带实验性质，接口可能在下一个版本变化。
- **数学块**：用过跨行 `$$` 的用户会感知到回退——alpha.2 里那套不稳定的兼容解析被撤掉了，行为回到之前。
- **自动化任务**：改成宿主级管理后，原来挂在会话里的任务在执行语义上可能有差异，建议先跑一个非关键任务验证。
