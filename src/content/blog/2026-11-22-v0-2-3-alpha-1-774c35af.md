让 Agent 整理一次项目周报，往往要跨好几个地方：去飞书或 Notion 找记录，把结论写进文档，最后交付一份能打开、版式正常的文件。任务一长，还得能看出来它已经做了什么、卡在哪里。

DeepSeek Harness 0.2.3-alpha.1 把这几个环节往同一个会话里推进了一步。第三方应用有了各自的连接器，Office 文件统一走一个 `office` 技能，实验性时间线能记录任务树和阶段报告。开发者最该留意的则是 PTC 默认执行方式变了，会话历史也多了一个可选的 SQLite 后端。

本文以 `dsh-v0.2.2-rc.5` 为基线，对照 11 月 22 日北京时间打出的 `dsh-v0.2.3-alpha.1` 标签（`d98f5d6`）。上一个 RC 标签已经进入新版本的历史，但两个标签的文件差异还包括此前并行开发、在这个 alpha 标签中一并纳入的主线工作。下文的功能与启用条件来自标签源码、文档和合入记录，尚未在安装包中逐项跑通。 [版本标签](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.3-alpha.1) · [两标签对比](https://github.com/deepseek-ai/deepseek-harness/compare/dsh-v0.2.2-rc.5...dsh-v0.2.3-alpha.1)

## 一、七个应用连接器，两种接入方式

这个标签里可以看到飞书、企业微信、腾讯会议、钉钉、Notion、Linear 和腾讯文档七个连接器。它们需要安装到相应的 profile，再连接对应的账号。能读取哪些资料、能执行哪些写入，取决于所用 CLI 或 MCP 工具以及账号权限。 [连接器总览](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.3-alpha.1/packages/connector/README.zh.md)

| 应用 | 怎么接入 |
| --- | --- |
| 飞书、企业微信、腾讯会议、钉钉 | 通过厂商 CLI 办理登录或授权。Harness 向模型提供 CLI 路径，用技能说明可执行的操作。 |
| Notion、Linear、腾讯文档 | 通过共用的 MCP 管理器连接厂商托管的 MCP 服务，在插件详情页发起 OAuth。 |

两条路径的区别，在遇到连不上时尤其有用。比如飞书先要有能运行的 `lark-cli`，它和本机终端共用 CLI 的默认账号配置，标签文档注明支持 macOS 和 Windows x64。Notion 则要先让当前 Host 完成 OAuth 授权，之后 Agent 才能按需加载该服务器里的工具。这种按需加载让 Agent 可以先看到有哪些能力，再把当前任务需要的工具加载进来。 [飞书插件](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.3-alpha.1/packages/connector/feishu/README.zh.md) · [Notion 插件](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.3-alpha.1/packages/connector/notion/README.zh.md) · [MCP 管理器](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.3-alpha.1/packages/mcp/mcp-manager/README.zh.md)

## 二、做文件统一用 /office，预览和重算有各自的工具

以前内置技能目录同时列出 `office`、`office-docx`、`office-pptx` 和 `office-xlsx`，这个版本把三个格式的指引收进一个 `office`。模型可以根据任务加载它，用户也可以输入 `/office`。在挂载了 Office 工具的组合里，成功加载技能后，下一步才会出现 `office_render`、`office_convert` 和 `office_recalculate`。 [Office 技能](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.3-alpha.1/packages/skill/skill-office/README.zh.md) · [合并 PR #8061](https://github.com/deepseek-ai/deepseek-harness/pull/8061)

比如做一份项目进度表，先用创作库写公式，再用 `office_recalculate` 生成可显示的结果。编辑 PPT 时，可以用 `office_render` 检查改过的页面有没有溢出。旧版 `.doc`、`.xls`、`.ppt` 可以先转换，Office 文件也可以经 `office_convert` 导出 PDF。渲染、转换和重算依赖可用的 LibreOffice Kit，预览效果也可能与微软原生 Office 不同。 [Office 工具](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.3-alpha.1/packages/document/tool-office/README.zh.md)

用过三个旧斜杠命令的用户，改用 `/office` 即可。维护自定义 profile 的人还要检查 `tool-office.activationSkills`。现在默认值只有 `office`，如果自己的技能也要激活这三个工具，需要在配置里明确列出。 [Office 升级指南](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.3-alpha.1/docs/upgrade-guide/v0.2.2-rc.5/office-single-skill/guide.zh.md)

## 三、时间线让长任务有地方记进度

同一个周报任务可以拆成收集资料、核对数据、起草正文和导出文件。启用时间线后，Agent 可以把这些工作写进会话里的任务树。用户可以从输入框上方的进度条打开侧栏，查看每项任务的结果、阻塞原因和更改记录，也能针对某项任务或某篇阶段报告发起讨论。 [时间线文档](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.3-alpha.1/packages/experimental/timeline/README.zh.md) · [集成 PR #7973](https://github.com/deepseek-ai/deepseek-harness/pull/7973)

进度条按任务权重和已记录的完成步数计算。比如权重为 3 的资料整理完成，权重为 1 的导出还没开始，这组任务就显示 75%。实际进度仍取决于 Agent 如何拆任务、何时更新。定时报告默认的最短间隔是 15 分钟、1 小时和 4 小时，上层报告会汇总下层已保存的报告。报告可能额外调用模型并消耗 Token。时间线是实验性插件，默认关闭，可从「插件 → 更多 → 时间线」开启。 [进度计算与报告设置](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.3-alpha.1/packages/experimental/timeline/README.zh.md)

## 四、界面上还有几处值得留意

- **个性化推荐移入通用设置。** Web 和桌面 profile 默认提供推荐卡片，开关移到「设置 → 通用设置 → 个性化推荐」。关闭后影响后续请求，已经展示的卡片仍可操作。不同轮次的提案也开始各自记录决定，新的提案出现后，前面未处理的提案仍可操作。 [默认推荐 #8647](https://github.com/deepseek-ai/deepseek-harness/pull/8647) · [独立卡片 #8900](https://github.com/deepseek-ai/deepseek-harness/pull/8900)
- **会话更容易回看。** 输入框支持用上下方向键召回已发送的输入。把会话拖到右侧栏，可以把它打开在那里。模型设置还支持编辑目录提供方模型的推理档位。 [输入历史 #8359](https://github.com/deepseek-ai/deepseek-harness/pull/8359) · [右侧栏 #8875](https://github.com/deepseek-ai/deepseek-harness/pull/8875) · [推理档位 #8827](https://github.com/deepseek-ai/deepseek-harness/pull/8827)
- **远程登录增加设备配对。** 新设备可以在未登录页面发起申请，已登录的所有者在「设置 → 远程连接」里批准。原有 Token 和二维码流程仍可用。配对成功会授予新浏览器所有者访问权限。 [配对 PR #7675](https://github.com/deepseek-ai/deepseek-harness/pull/7675) · [远程连接说明](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.3-alpha.1/packages/client/remote-connection/README.zh.md#pairing-requests)
- **Forge 增加独立代码评审页与 GitLab MR 接入。** 独立页可以查看当前登录用户参与的变更请求，也能按 URL 打开评审。具体可用的评审操作取决于托管平台提供方和账号权限。 [评审页 #8321](https://github.com/deepseek-ai/deepseek-harness/pull/8321) · [GitLab MR #8317](https://github.com/deepseek-ai/deepseek-harness/pull/8317)

## 五、升级自定义 profile 时，先看这几项

**Node PTC 默认改为持久 scoped REPL。** 以前省略 `executionMode` 时，每次 `run_code` 在新进程的 async 函数体里运行。现在默认每个存活的 Agent 保留一个 Node 进程，顶层变量可以留到下一次调用。旧脚本里用于返回结果的顶层 `return value` 要改为最后一条表达式 `value`，或者显式配置 `executionMode: per-call`。受影响的还包括使用同一默认运行时的 workflow-ptc 脚本。 [PTC 升级指南](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.3-alpha.1/docs/upgrade-guide/v0.2.2-rc.5/ptc-default-scoped-repl/guide.zh.md) · [PR #8848](https://github.com/deepseek-ai/deepseek-harness/pull/8848)

**SQLite 可以存会话历史，内置 profile 继续用 JSONL。** 选择 SQLite 持久化提供者后，首次打开已有会话时会导入旧 JSONL，保留源文件，后续事件写入 SQLite。每个 Session 仍只允许一个写者，但可以在写入时读取。实现还加入了压缩帧和分组提交。两个标签的会话格式版本常量都是 V4，这和持久化提供者的选择是两回事。 [SQLite 提供者文档](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.3-alpha.1/packages/session/session-persistence-sqlite/README.zh.md) · [持久化 PR #8391](https://github.com/deepseek-ai/deepseek-harness/pull/8391) · [V4 常量](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.3-alpha.1/packages/core/session/src/types.ts#L90)

**Computer Use 调整了输入接口。** macOS 的 `useSystemPointer` 改名为 `useSystemInput`，覆盖鼠标和部分键盘方法，配套的能力字段和授权配置也改了名。macOS 和 Windows 的显式按下操作在成功后可以跨程序、跨轮次保持，工具会提醒哪些键或按钮仍按着，调用方要在合适的时候显式释放。这里涉及三项独立变化：平台可用性、系统输入的授权和显式按下的生命周期。 [Computer Use 平台说明](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.3-alpha.1/packages/experimental/cua-bundle/README.zh.md) · [系统输入迁移](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.3-alpha.1/docs/upgrade-guide/v0.2.2-rc.5/cua-system-input/guide.zh.md) · [持有输入迁移](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.3-alpha.1/docs/upgrade-guide/v0.2.2-rc.5/cua-held-inputs/guide.zh.md)

**SDK 的日期解释有了默认时区。** TypeScript 和 Python SDK 的普通 prompt 省略时区时，模型收到的是运行时进程的时区。部署在 UTC 容器里的应用，如果要按用户所在地理解「明天上午九点」，可以在调用时显式传入用户时区，例如 `Asia/Shanghai`。 [SDK 时区升级指南](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.3-alpha.1/docs/upgrade-guide/v0.2.2-rc.5/sdk-prompt-time-zone/guide.zh.md)

回到周报的例子，这个 alpha 里最值得试的是一条完整路径：接入一个已有资料源，让 Agent 整理一份带公式的表格，用 Office 工具检查计算结果，再去时间线看它如何记录完成和阻塞。连接器、文件工具和进度记录各自解决一项具体工作。至于已有自动化能不能直接升级，取决于 profile 是否依赖旧的 Office 技能名、PTC 函数体语法或 Computer Use 参数。
