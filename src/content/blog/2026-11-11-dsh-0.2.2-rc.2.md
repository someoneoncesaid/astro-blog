## 三、三条新增功能

### 1. Git Worktree：把代码审阅搬进 DSH

支持按**分支、提交、文件类型**筛阅改动，直接处理 GitHub 评审、同步已审阅（viewed）进度、更新分支。配套体验优化还包括评论、文件导航、窄屏布局、大改动卡顿与大仓库建树等待时间。

代码核对（`packages/experimental/`）：

- `client-ui-forge/src/client/ChangesTab.tsx`：`ForgeLocalScope`（`branch` / `uncommitted` / `change`）、commit picker、`ChangesLens`（`interface` / `implementation` / `test`）。**该骨架在 rc.1 已存在**。
- `rc.2 新增`：`changeRequestViewed`（已审阅进度）与 `forge-github/src/review-writes.ts` 的 `writeGitHubReview`（`ADD_REVIEW_MUTATION` / `SUBMIT_REVIEW_MUTATION`）；`forge/src/types.ts` 有 `branchUpdates`。
- 即：**筛选框架是既有能力，GitHub 评审写入 + viewed 同步才是本阶段的增量**，写稿时不要说成「Worktree 审阅功能首次上线」。

## 六、写稿前必须注意的几处措辞

1. **Fetch 没改成 DeepSeek**：只有 `searchProvider` 默认值变了，`fetchProvider` 默认仍是 `http`；「搜索与获取可分别选择计费账号或 API Key」指两项**能力可分别配置**，不是两者默认都切到 DeepSeek。

### Agent 终端：读取后进入模型上下文（轨迹验证）

独立 `rc2-terminal` profile 启用实验性持久终端 bundle，使用真实 GLM-5.3-Flash 模型。模型先用 `terminal_open` / `terminal_send` 创建侧栏 Agent 终端；用户输入后接管终端。随后让模型只读该终端，聊天提示中没有给出 Case、Environment、Issue 的具体值。

![侧栏终端与模型读取后的回复对照](/posts/2026-11-11-dsh-0.2.2-rc.2/assets/73f2e52c2309.jpg)

![轨迹中 user_terminal_read 的完整工具结果](/posts/2026-11-11-dsh-0.2.2-rc.2/assets/750603a8e917.jpg)
